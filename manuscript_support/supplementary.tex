\section{Purpose and submission boundary}

This supplement contains only details that support the current reporting-method research questions: task-specific population flow, source-rule validity, representation-level information retention, record-contract invariants, bounded second-pipeline instantiation, trace cases, and artifact verification. They are retained only in the artifact's \path{history/} directory as non-contributory chronology.

\section{Source-syntax validity-case protocol}

The production SA-001 rule is the conjunction of GEB scope and the lexical predicate \texttt{dt\_FB\_} in \texttt{core\_symbol\_text}. The transfer probe removes only the GEB scope condition. It does not modify the lexical predicate, use source labels during matching, or write back to production cards. OpenPLC rows are therefore \texttt{OUT\_OF\_SCOPE} for the production rule and are scored only for the ungated probe.

The oracle removes Structured Text comments and extracts line-anchored \texttt{FUNCTION\_BLOCK}, \texttt{FUNCTION}, and \texttt{PROGRAM} declarations. Binary and source rows join by normalized program stem within one toolchain. Multiple source files are accepted only when they agree on explicit \texttt{FUNCTION\_BLOCK} presence. The current complete mapped population contains 617 GEB, 619 OpenPLC v2, and 640 OpenPLC v3 rows. Because the rule was developed and checked on the same snapshot, the GEB result is a post-hoc validity case rather than prospective accuracy.

\section{Fold-wise signature decoder}

Let $s_m(x)$ denote the categorical signature of sample $x$ under representation $m\in\{S2,S3,S6\}$. For held-out fold $k$, the decoder assigns the majority target among training rows with the same signature:

\begin{equation}
\widehat{y}_{m,k}(x)=
\begin{cases}
\operatorname{majority}\{y_j:s_m(x_j)=s_m(x),\,j\notin k\}, & \text{if observed},\\
\operatorname{majority}\{y_j:j\notin k\}, & \text{otherwise}.
\end{cases}
\end{equation}

Ties resolve deterministically toward the numerically smaller class. No held-out row has an unseen signature. \texttt{S2} contains EC1 and EC6; \texttt{S3} contains EC1, EC4, and EC6; \texttt{S6} contains EC1--EC6. This is an information-retention test, not a production classifier or an analyst-utility experiment.

\section{Bounded second-pipeline instantiation}

The adapter joins a 56-row native manifest to 6{,}657 relation rows and 20 uncertainty rows by \texttt{sample\_id} and SHA-256. It emits 10 cards for binaries with bilateral relation evidence. Function identifiers, static relation counts, graph-edge counts, hint counts, and uncertainty stages map into the existing slot vocabulary; CVE and patch-role fields remain provenance rather than behavioral labels.

All 10 analyzed binaries are OpenPLC-derived GCC/x86-64 artifacts, nine at O0 and one at project-O2. The mapping was implemented by the authors, and no independently sampled adapter failure set exists. This is a bounded contract-instantiation smoke test, not compiler, vendor, architecture, or schema portability.

\section{Schema coverage and content-validity boundary}

All EC slots occur in the 2{,}431-card population. EC1, EC2, EC3, and EC5 contain 1{,}876 filled and 555 partial rows; EC4 contains 475 filled and 1{,}956 partial rows; EC6 is filled for all rows. U01, U02, U11, U13, and U09b occur. The other defined U-codes are unobserved in the primary population.

Observed coverage does not prove category necessity, sufficiency, or saturation. No independent coding or expert content-validation result exists. The artifact therefore includes a \texttt{TEMPLATE\_ONLY} counterbalanced reviewer-task protocol and empty response table. Neither is counted as empirical evidence until independent humans complete it under the required ethics or institutional process.

\section{Forbidden claims}

SCAA-PLC does not claim human-utility improvement, complete or sound semantic recovery, vulnerability detection, compiler/vendor/architecture portability, universal CODESYS opacity, a complete uncertainty taxonomy, comparative superiority, supply-chain analysis, or SBOM generation. The independent-review protocol cannot be cited as a result until completed.

\section{Artifact integrity and acquisition policy}

The release candidate contains author-generated derived data, scripts, checksums, environment notes, and clean-room verification logs. It excludes raw PLC-BEAD binaries and sources because the examined upstream snapshot contains no explicit license file. Reviewers acquire the public snapshot separately and run the supplied verifier, which compares binary and source hashes against the evidence-card and source-oracle records. Cross-pipeline raw binaries are also excluded; only derived manifest, relation, and uncertainty tables required by the reporting analysis are included.

The package is not public until the authors select code/data licenses and upload the fixed directory to a reviewer-accessible repository or archive. A GitHub URL alone should be paired with a release tag; a persistent DOI is recommended for the submission version~\cite{heumueller_software_artifacts2020}.
